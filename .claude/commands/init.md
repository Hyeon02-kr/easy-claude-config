# 프로젝트 초기화 (커스텀 /init)

새 프로젝트 또는 기존 프로젝트를 초기 설정한다. 아래 순서를 그대로 따른다.

## 1. 중요도 질문 (가장 먼저)

AskUserQuestion으로 현재 프로젝트의 중요도를 3단계 중 하나로 확인한다:

* **토이/개인** — 실험적, 개인용, 부담 없는 프로젝트
* **업무** — 실제로 쓰이거나 협업하는 일반 프로젝트
* **중요/민감** — 프로덕션, 금융, 민감 데이터 등 실수 시 피해가 큰 프로젝트

이후 모든 단계는 이 선택 결과에 따라 분기한다.

## 2. 변경 사항 미리보기 및 확인

실제로 파일을 쓰기 전에, 1번에서 정해진 등급을 바탕으로 무엇이 어떻게 바뀔지 요약해서 보여주고 확인받는다. 파일 시스템·권한 변경은 되돌리기 비용이 있으므로 이 확인은 생략하지 않는다.

* `.gitignore`:
  * 이미 존재하면 "기존 파일 유지, 손대지 않음"이라고 명시한다.
  * 없으면 새로 생성할 언어별 기본 항목 + 등급별 추가 항목을 나열한다.
* `.claude/settings.json`:
  * 없으면 새로 생성할 permissions 내용 전체를 보여준다.
  * 이미 있으면 먼저 읽고, **추가/변경될 항목만 diff 형태로**("기존에 없던 다음 규칙이 추가됩니다: ...") 보여준다.
  * 기존 규칙과 충돌하면(같은 키가 이미 다른 값으로 설정됨) 절대 조용히 덮지 않고 어떻게 처리할지 사용자에게 묻는다.
* 로컬 `CLAUDE.md`: 새로 추가될 "프로젝트 중요도" 줄과, 토이 등급이면 추가될 커밋 권한 선언 문구를 보여준다.

위 내용대로 진행해도 되는지 확인받은 뒤에만 3단계로 넘어간다.

## 3. 사전 자동화 작업 (2단계에서 확인된 내용을 실행)

* `.git` 폴더가 없으면 `git init` 실행.
* `docs/` 폴더가 없으면 생성.
* `.gitignore`:
  * 이미 존재하면 손대지 않는다.
  * 없으면 프로젝트 파일(package.json, requirements.txt, *.csproj 등)을 보고 언어/프레임워크를 판단해 기본 템플릿을 작성한다.
  * 등급별로 아래 항목을 추가한다:
    * 토이: 언어별 기본 항목만 (추가 제한 없음)
    * 업무: 위 + `.claude/`
    * 중요: 위 + `.claude/` + `docs/`
* `.claude/settings.json`이 없으면 생성하고, 있으면 기존 내용을 보존한 채 병합한다. 등급별 `permissions` 규칙:
  * **토이** → `allow`에 추가:
    ```json
    ["Bash(git commit *)", "Bash(git push *)"]
    ```
  * **업무** → `ask`에 추가:
    ```json
    ["Bash(git commit *)", "Bash(git push *)"]
    ```
  * **중요** → `deny`에 추가:
    ```json
    [
      "Bash(git commit *)", "Bash(git push *)",
      "Bash(git push --force*)", "Bash(git reset --hard*)",
      "Bash(git clean -f*)", "Bash(git branch -D*)",
      "Bash(rm -rf*)",
      "PowerShell(git push --force*)", "PowerShell(git reset --hard*)",
      "PowerShell(git clean -f*)", "PowerShell(git branch -D*)",
      "PowerShell(Remove-Item -Recurse -Force*)"
    ]
    ```
* 토이 등급이면, 로컬 `CLAUDE.md`에 아래 선언 문구를 추가한다 (없을 경우에만):
  > 이 프로젝트는 개인/토이 프로젝트입니다. Claude는 사용자 승인 없이 `git commit`/`git push`를 직접 실행할 수 있습니다.

## 4. 로컬 CLAUDE.md 본문 작성

* 프로젝트에 실질적인 내용(소스 코드, 설정 등)이 이미 있으면: 구조, 기술 스택, 빌드/테스트/실행 명령, 컨벤션 등을 스캔해서 문서화한다.
* 내용이 비어 있으면: 사용자에게 "어떤 프로젝트로 만들 계획인지" 한 줄로 질문하고, 답변을 바탕으로 "현재 빈 프로젝트이며, 계획: ..." 형태로 명시하는 CLAUDE.md를 작성한다.
* 두 경우 모두 CLAUDE.md에 "프로젝트 중요도: 토이/업무/중요" 한 줄을 기록한다.

## 5. 전역 메모리에 프로젝트 등록

프로젝트별 auto-memory 경로가 아니라, **항상 고정된 홈 디렉터리 메모리 경로**(`~`를 프로젝트 루트로 볼 때의 auto-memory 디렉터리, 즉 `~/.claude/projects/<홈 디렉터리 경로를 sanitize한 이름>/memory/`)에 기록한다 (다른 프로젝트 작업 시에도 참고할 수 있도록).

* 해당 경로에 `project_<프로젝트slug>.md` 파일 생성 (frontmatter: `name`, `description`, `metadata.type: project`).
* 본문: 프로젝트명, 절대 경로, 중요도 등급, 한 줄 목적/설명, 생성일(오늘 날짜).
* 같은 경로의 `MEMORY.md` 인덱스에 한 줄 추가 (`- [프로젝트명](project_<slug>.md) — 한줄 설명`).

## 6. 완료 요약 및 자체 검증

작업이 끝나면 아래를 확인하고 사용자에게 보고한다.

* 생성/수정된 파일 목록을 나열한다.
* 자체 검증:
  * `.claude/settings.json`이 유효한 JSON인지 확인한다.
  * 로컬 `CLAUDE.md`에 미채움 상태의 안내 문구(예: "계획: ...")가 남아있지 않은지 확인한다.
  * `.gitignore`에 추가하기로 한 항목이 실제로 파일에 반영됐는지 확인한다.
* 등급별로 사용자가 직접 해야 하는 후속 조치를 안내한다:
  * 토이: 별도 후속 조치 없음.
  * 업무: 팀원에게 CLAUDE.md·권한 정책 공유를 권장한다고 안내한다.
  * 중요: 원격 저장소의 브랜치 보호(protected branch) 설정, 강제 push 차단 등 스킬이 대신 설정할 수 없는 항목을 직접 켜도록 안내한다.
